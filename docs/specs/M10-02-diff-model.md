## 1. Goal

Turn the server's patches into a render model the view can draw without parsing
anything per frame: files, hunks, and typed lines, with explicit handling for
binary files, renames, truncation, CRLF, and malformed input.

## 2. Verified contract

| Endpoint | Shape |
| --- | --- |
| `GET /api/vcs/diff` | query `location[directory]`, `mode` (`working\|branch\|committed`), `base`, `context`, `untracked` (`files\|folders`) → `{location, data: [FileDiff.Info]}` |
| `GET /api/session/{sessionID}/diff` | query `from`, `to`, `context` → `{data: [FileDiff.Info]}` |

`FileDiff.Info` = `{file, patch, additions, deletions, status, more}`.
`more: true` means the server truncated the patch; `patch` may be empty for a
binary file. Errors: 404 `MessageNotFound`, 503 `ServiceUnavailable`.

Verified 2026-11-10 on v2.2.6: the server builds its working-tree snapshot from
its file watcher. Before the first filesystem event after startup, status and
diff can both be empty even for a modification made before launch. The app
refreshes on `filesystem.changed` (M10-01); the e2e test touches a file and
retries until the snapshot includes the change.

## 3. Protocol

```rust
pub struct FileDiff { pub file: String, pub patch: String, pub additions: u64,
                      pub deletions: u64, pub status: String, pub more: bool }
```

`patch` is untrusted text. It is never rendered as HTML and never executed.

## 4. Core parser

`parse_patch(&FileDiff) -> ParsedDiff` in `harness-core/src/diff.rs`:

```rust
pub struct ParsedDiff { pub files: Vec<FilePatch>, pub truncated: bool, pub binary: bool }
pub struct FilePatch { pub old_path: Option<String>, pub new_path: Option<String>,
                       pub status: VcsChange, pub hunks: Vec<Hunk>, pub binary: bool }
pub struct Hunk { pub old_start: u32, pub old_lines: u32, pub new_start: u32,
                  pub new_lines: u32, pub header: String, pub lines: Vec<DiffLine> }
pub struct DiffLine { pub kind: DiffLineKind, pub text: String, pub old_no: Option<u32>,
                      pub new_no: Option<u32> }
pub enum DiffLineKind { Context, Added, Removed, Meta }
```

Rules:

- Recognize `diff --git`, `---`, `+++`, `@@`, `new file mode`, `deleted file
  mode`, `rename from/to`, `similarity index`, `Binary files … differ`, and
  `\ No newline at end of file`.
- An unknown line inside a hunk is `Context`; it never aborts the parse.
- A hunk ends at the next `@@` or `diff --git`; a short hunk is accepted.
- Limits: 4 MB per patch and 50,000 lines total; beyond that set
  `truncated = true` and stop, keeping whole files only.
- `more: true` or a binary marker sets `binary`/`truncated` and the view shows
  a notice instead of an empty box.
- CRLF is normalized for display; the model keeps the text without `\r`.

## 5. Engine

Commands `LoadVcsDiff{request_id, mode, base, context, untracked}` and
`LoadSessionDiff{request_id, session_id, from, to, context}`. Events
`VcsDiffLoaded{request_id, result}` and `SessionDiffLoaded{request_id, result}`.

Parsing happens in the supervisor on the engine thread, never in `Render`.
The event carries the `ParsedDiff`, so the view only maps rows to elements.

Resnapshot: the panel reloads the diff when the selected file changes, on
`StreamConnected`, and after a turn ends (`session.step.ended`).

## 6. UI

No UI in this node; M10-03 consumes the model. The only requirement here is
that `ParsedDiff` is `Clone` and cheap to iterate by reference.

## 7. Non-goals

Applying patches, word-level diffs, image diffs, three-way merges.

## 8. Tests

| Crate | Test | Proves |
| --- | --- | --- |
| protocol | `file_diff_parses_more_and_counts` | wire shape |

| core | `patch_keeps_no_newline_marker` | marker line |

Fixtures under `crates/protocol/tests/fixtures/diff/`: `rename.patch`,
`binary.patch`, `crlf.patch`, `malformed.patch`, `big.patch` (generated by the
test, not committed).

E2E (`tests/M10-02.rs`, no model gate): temp git repo, modify and add files,
`LoadVcsDiff` with `mode=working`, assert the parsed file count and that the
sum of `Added + Removed` lines equals the server's `additions + deletions` for
a text file. Durable assertion: the patch matches `git diff` for the same file.

## 9. Acceptance

- [ ] A 5,000-line patch parses in under 50 ms in a release build (recorded).
- [ ] Malformed input never panics; the file still appears with a notice.
- [ ] Rename and binary files are represented, not dropped.
- [ ] Truncation is visible, never silent.

## 10. Risks

Patch dialects vary by git version. The parser is intentionally permissive and
the e2e test compares against real `git diff`, not a hand-written string.
