## 1. Goal

Settings → MCP lists every server with its status, lets the user add or remove
a runtime server, and shows a plain warning that runtime-only changes may not
survive a sidecar restart. The app never writes `opencode.json`.

## 2. Verified contract

| Endpoint | Shape |
| --- | --- |
| `GET /api/mcp` | query `location[directory]` → `{location, data: [Mcp.Server]}` |
| `GET /api/mcp/resource` | resources of connected servers |
| `PUT /api/experimental/mcp/{server}` | add or replace a server |
| `DELETE /api/experimental/mcp/{server}` | remove |
| `POST /api/experimental/mcp/{server}/connect` | connect |
| `POST /api/experimental/mcp/{server}/disconnect` | disconnect |

`Mcp.Server` = `{name, status, title?, integrationID?}`. `status` is
`Connected | Pending | Disabled | Failed | NeedsAuth`, each an object with a
`status` tag plus optional `error`/`ref`. The NeedsAuth tag is `needs_auth`
(not `needs-auth`). Events: `mcp.status.changed`, `mcp.resources.changed`, both
carrying only `{server}`; the list must be reloaded to see the new status.

## 3. Protocol

```rust
pub enum McpStatus { Connected, Pending, Disabled, NeedsAuth,
                     Failed { error: String }, Unknown { raw: String } }

pub struct McpServer { pub name: String, pub status: McpStatus,
                       pub title: Option<String>, pub integration_id: Option<String> }
```

Fixture: one server per status, plus `{"status":"warming"}` → `Unknown`.

## 4. Engine

Commands `ListMcp{request_id}`, `AddMcp{name, config}`, `RemoveMcp{name}`,
`ConnectMcp{name}`, `DisconnectMcp{name}`. Events `McpLoaded{request_id,
result}`, `McpChanged`, `McpError{name, message}`.

Resnapshot: reload on `StreamConnected` and on `mcp.*` events (debounced
250 ms).

## 5. Core

`McpStore` keyed by name; `replace`, `upsert`, `remove`. Rules:

- A `Failed` server keeps its error text for display, truncated to 400 chars.
- `NeedsAuth` offers Connect; `Connected` offers Disconnect; `Disabled` is
  read-only in the app.
- After add/remove/connect, reload from the server; never assume success.

## 6. UI

A list with a status dot, name, title, and actions. "Add server" takes a JSON
object (validated before send) and shows the runtime-only caveat with a "Copy
config" button that puts a snippet on the clipboard for `opencode.json`.
Deleting asks for confirmation.

## 7. Non-goals

Editing `opencode.json`, OAuth for MCP servers beyond the integration flow
(M13-02), browsing MCP resources beyond a read-only count.

## 8. Tests

| Crate | Test | Proves |

| protocol | `mcp_status_parses_every_variant` | five statuses |
| protocol | `mcp_unknown_status_is_kept` | forward compatibility |

| core | `mcp_add_then_reload_is_authoritative` | no optimistic state |
| engine | `mcp_add_body_is_valid_json` | validation |

E2E (`tests/M13-01.rs`, no model gate): list on a fresh project, add a stdio
server that runs the test-owned `mcp-echo` fixture, wait for `connected`,
disconnect and observe `disabled`, connect again, then remove and assert it is
gone. It also removes a missing name and asserts the server's 404-shaped error
surfaces, and it compares `opencode.json` before and after to prove the app did
not write it. The fixture answers the MCP handshake over newline-delimited
JSON-RPC; see the implementation notes for why it is a bin target.

## 9. Acceptance

- [x] The list shows status and survives a refresh.
- [x] Add/remove reach the server and are reflected after reload.
- [x] The restart caveat is visible on the same screen.
- [x] No write to the project's OpenCode config.

## 10. Implementation notes

Live probe against opencode v2.2.7 (2026-11-11):

- `PUT /api/experimental/mcp/{server}` requires `{"config": {...}}` and returns
  204. The config is `Mcp.LocalConfigEncoded` (`type`: `local`, `command`:
  array) or `Mcp.RemoteConfigEncoded` (`type`: `remote`, `url`), with
  `disabled`, `environment`, `headers`, `timeout`, `protocol`, `pool`, and
  `codemode` options. `opencode.json` nests the same objects under
  `mcp.servers`.
- `connect` and `disconnect` return 204; disconnect turns a connected server
  into `disabled`. Remove (`DELETE`) returns 204 and the server disappears from
  the list. Acting on a missing server returns 404
  `{"_tag":"McpServerNotFoundError",...}`.
- Runtime-added servers have no `title` or `integrationID`; both stay optional.
- A stdio server that answers `initialize`, `tools/list`, `resources/list`, and
  `prompts/list` over newline-delimited JSON-RPC reaches `connected`.
- The test fixture is a `[[bin]]` target (`crates/engine/tests/fixtures/
  mcp_echo.rs`, bin name `mcp-echo`) instead of a `--mcp-echo` mode of the test
  binary: Cargo integration tests run through libtest, which rejects unknown
  flags, and `CARGO_BIN_EXE_mcp-echo` gives the test a stable path.
- The 250 ms coalescing lives in the view: `StreamEvent::McpChanged` sets a due
  time, and the existing 250 ms tick reloads the list once the events settle.
  The mutation events from the engine still reload immediately.
- "Copy config" copies `{"mcp":{"servers":{<name>:<config>}}}`, using the
  values in the add form when they are valid or a local-command template
  otherwise.

## 11. Risks

The experimental endpoints may change. They are isolated in one feature
module; a shape change breaks one node, not the app.
