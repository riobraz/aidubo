## 1. Goal

Settings → MCP lists every server with its status, lets the user add or remove
a runtime server, and shows a plain warning that runtime-only changes may not
survive a sidecar restart. The app never writes `opencode.json`.

## 2. Verified contract

| Endpoint | Shape |
| --- | --- |
| `GET /api/mcp` | query `location[directory]` → `{location, data: [Mcp.Server]}` |
| `GET /api/mcp/resource` | resources of connected servers |
| `PUT /api/experimental/mcp/{server}` | add or replace a server |
| `DELETE /api/experimental/mcp/{server}` | remove |
| `POST /api/experimental/mcp/{server}/connect` | connect |
| `POST /api/experimental/mcp/{server}/disconnect` | disconnect |

`Mcp.Server` = `{name, status, title?, integrationID?}`. `status` is
`Connected | Pending | Disabled | Failed | NeedsAuth`, each an object with a
`status` tag plus optional `error`/`ref`. Events: `mcp.status.changed`,
`mcp.resources.changed`.

## 3. Protocol

```rust
pub enum McpStatus { Connected, Pending, Disabled, NeedsAuth,
                     Failed { error: String }, Unknown { raw: String } }

pub struct McpServer { pub name: String, pub status: McpStatus,
                       pub title: Option<String>, pub integration_id: Option<String> }
```

Fixture: one server per status, plus `{"status":"warming"}` → `Unknown`.

## 4. Engine

Commands `ListMcp{request_id}`, `AddMcp{name, config}`, `RemoveMcp{name}`,
`ConnectMcp{name}`, `DisconnectMcp{name}`. Events `McpLoaded{request_id,
result}`, `McpChanged`, `McpError{name, message}`.

Resnapshot: reload on `StreamConnected` and on `mcp.*` events (debounced
250 ms).

## 5. Core

`McpStore` keyed by name; `replace`, `upsert`, `remove`. Rules:

- A `Failed` server keeps its error text for display, truncated to 400 chars.
- `NeedsAuth` offers Connect; `Connected` offers Disconnect; `Disabled` is
  read-only in the app.
- After add/remove/connect, reload from the server; never assume success.

## 6. UI

A list with a status dot, name, title, and actions. "Add server" takes a JSON
object (validated before send) and shows the runtime-only caveat with a "Copy
config" button that puts a snippet on the clipboard for `opencode.json`.
Deleting asks for confirmation.

## 7. Non-goals

Editing `opencode.json`, OAuth for MCP servers beyond the integration flow
(M13-02), browsing MCP resources beyond a read-only count.

## 8. Tests

| Crate | Test | Proves |
| --- | --- | --- |
| protocol | `mcp_status_parses_every_variant` | five statuses |
| protocol | `mcp_unknown_status_is_kept` | forward compatibility |
| core | `mcp_snapshot_replaces_and_keeps_errors` | error text |
| core | `mcp_add_then_reload_is_authoritative` | no optimistic state |
| engine | `mcp_add_body_is_valid_json` | validation |

E2E (`tests/M13-01.rs`, no model gate): list on a fresh project, add a stdio
server that runs the test binary's own `--mcp-echo` mode (a 20-line fixture in
`support`), assert it appears, connect or observe `Pending`, then remove and
assert it is gone. If the runtime endpoint rejects stdio, the test records the
exact error and asserts the server is not listed — it must not silently pass.

## 9. Acceptance

- [ ] The list shows status and survives a refresh.
- [ ] Add/remove reach the server and are reflected after reload.
- [ ] The restart caveat is visible on the same screen.
- [ ] No write to the project's OpenCode config.

## 10. Risks

The experimental endpoints may change. They are isolated in one feature
module; a shape change breaks one node, not the app.
